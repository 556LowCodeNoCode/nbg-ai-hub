# Αυτοματοποίηση Σύνταξης Συμβάσεων Προμηθευτών — Ανάλυση, Data Model & Κανόνες

**Πεδίο ανάλυσης:** 8 έγγραφα (4 πρότυπα + 4 υπογεγραμμένες εφαρμογές) στον φάκελο `LEGAL CONTRACTS`
**Ημερομηνία:** 2026-08-03
**Σκοπός:** Ορισμός των κατηγοριών εγγράφων, του data model ανά κατηγορία, των κανόνων εμφάνισης άρθρων, και των εκκρεμών ερωτημάτων προς τον πελάτη.

---

## 0. Σύνοψη ευρημάτων

| | |
|---|---|
| **Κατηγορίες εγγράφων** | 3 οικογένειες συμβάσεων + 1 τροποποιητικό όργανο |
| **Βαθμός τυποποίησης** | Υψηλός: το ~85–90% του κειμένου είναι σταθερό boilerplate που δεν αλλάζει ανά ανάδοχο |
| **Μεταβλητά πεδία** | ~55–66 placeholders ανά πρότυπο (μετρημένα) — αλλά αντιστοιχούν σε **~40 λογικά πεδία**, γιατί το ίδιο πεδίο επαναλαμβάνεται (π.χ. διάρκεια εμφανίζεται 4–6 φορές) |
| **Κρίσιμο εύρημα** | Τα πρότυπα είναι **μολυσμένα** με στοιχεία προηγούμενων συμφωνιών· και υπάρχει **υπογεγραμμένο** έγγραφο με ασυμπλήρωτα placeholders |

Η αυτοματοποίηση δεν είναι απλώς «γρηγορότερη» — λύνει ένα υπαρκτό ποιοτικό πρόβλημα που τεκμηριώνεται στην §5.

### 1.1 Πώς διακρίνονται μεταξύ τους (decision logic για αυτόματη επιλογή template)

Η επιλογή προτύπου μπορεί να παραχθεί αυτόματα από στοιχεία που ήδη υπάρχουν στη ροή προμήθειας:

```
ΕΡΩΤΗΜΑ 1: Υπάρχει ενεργή αρχική σύμβαση που τροποποιείται/ανανεώνεται;
  ΝΑΙ  → Κατηγορία D (ADDENDUM)
  ΟΧΙ  → ΕΡΩΤΗΜΑ 2

ΕΡΩΤΗΜΑ 2: Το αντικείμενο περιλαμβάνει άδειες χρήσης λογισμικού / παράδοση
           Συστήματος με τυπική διαδικασία Προσωρινής & Οριστικής Παραλαβής;
  ΝΑΙ  → Κατηγορία A (IT PLATFORM)
  ΟΧΙ  → ΕΡΩΤΗΜΑ 3

ΕΡΩΤΗΜΑ 3: Πρόκειται για συνεχή/επαναλαμβανόμενη υπηρεσία (SaaS, managed
           service, συνδρομή) με ετήσιο κόστος και SLA διαθεσιμότητας;
  ΝΑΙ  → Κατηγορία B (IT SOLUTION)
  ΟΧΙ  → Κατηγορία C (IT CONSULTING – FIXED SCOPE)
```

## 3. Σταθερό vs μεταβλητό περιεχόμενο

| Ζώνη | Περιεχόμενο | Χειρισμός |
|---|---|---|
| **Ζώνη 1 — Αμετάβλητο boilerplate** (~85%) | Εμπιστευτικότητα, GDPR, BRRD/Μέτρα Εξυγίανσης, Δικαιώματα Ελέγχου ΤτΕ, Ανωτέρα Βία, Διαχωρισμός, Επικεφαλίδες, Δέσμευση Διαδόχων, Καταπολέμηση Διαφθοράς | Κλειδωμένο· καμία ανθρώπινη παρέμβαση· έκδοση (versioning) κεντρικά από Νομική |
| **Ζώνη 2 — Παραμετρικό** (~10%) | Στοιχεία μερών, ποσά, ημερομηνίες, ορόσημα, ποσοστά ρητρών, παραρτήματα | Auto-fill από το data model |
| **Ζώνη 3 — Υπό όρους** (~4%) | Escrow, υπεργολάβοι, εγγυητική, SLA, μεταβατική υποστήριξη, εξοπλισμός | Κανόνες §4 |
| **Ζώνη 4 — Ελεύθερο κείμενο** (~1%) | Περιγραφή αντικειμένου, περιγραφές οροσήμων, ειδικές διαπραγματευμένες ρήτρες | **Πάντα human review** |

## 4. Κανόνες άρθρων / ενοτήτων

Κωδικοποίηση: `R-xx` · **Trigger** = συνθήκη από το data model · **Action** = τι συμβαίνει στο έγγραφο.

| ID | Κανόνας | Trigger | Action |
|---|---|---|---|
| **R-01** | Μπλοκ υπογραφών | `count(bank.signatories)` | 1 υπογράφων → 1 κελί· 2 → 2 κελιά· 3 → προσθήκη 2ης σειράς πίνακα. Ίδιο για ανάδοχο. |
| **R-02** | Ρήτρα cloud/SaaS στο Άρθρο 2 (Α) | `system.delivery_model == SaaS-cloud-vendor` | Εμφάνιση «…με τη μορφή υπηρεσιών (Software-as-a-Service) σε υποδομές cloud της Εταιρείας». Αν `on-prem` → παραλείπεται και αλλάζει η διατύπωση παράδοσης. |
| **R-03** | Άρθρο GDPR (Επεξεργασία Προσωπικών Δεδομένων) | `processes_personal_data == true` | Εμφάνιση πλήρους άρθρου + Παραρτήματος GDPR. **Αν false → όλο το άρθρο και το παράρτημα αφαιρούνται** (όπως στην Κατηγορία C). |
| **R-04** | Ρήτρα εγκεκριμένων υπεργολάβων (Α, άρθρο 13.2) | `len(approved_subcontractors) > 0` | Εμφάνιση της πρότασης «…θα παρασχεθούν από την εταιρεία X…, ως εγκεκριμένων υπεργολάβων». **Αν 0 → η πρόταση διαγράφεται εξ ολοκλήρου** (σήμερα μένει με ονόματα άσχετου προμηθευτή). |
| **R-05** | Ρήτρα Escrow πηγαίου κώδικα (Α, άρθρο 19) | `escrow.applies == true` | Εμφάνιση παραγράφου με `software.manufacturer` + προθεσμία συναίνεσης. Αν false → παραλείπεται. |
| **R-06** | Εγγυητική Επιστολή Καλής Εκτέλεσης | `contract_value ≥ threshold` **ή** πολιτική ανά κατηγορία | A: υποχρεωτική (10% + ρήτρα αύξησης σε επεκτάσεις)· B/C: υπό όρους· D: μόνο αν ανανεώνεται/μεταβάλλεται. **Το threshold είναι εκκρεμές — Q-02.** |
| **R-07** | Μεταβατική υποστήριξη υφιστάμενης εγκατάστασης (B) | `transition.legacy_support == true` | Εμφάνιση παραγράφου SLA on-prem + αντίστοιχου πίνακα ρητρών. Αν false → παραλείπεται. |
| **R-08** | Παράγραφος προμήθειας εξοπλισμού (B, άρθρο 4) | `hardware.included == true` | Εμφάνιση tranche πληρωμής «…για την προμήθεια του …, εντός 45 ημερών από την παράδοση». |
| **R-09** | Προθεσμία πληρωμής | κατηγορία | A & C → **60 ημέρες**· B → **45 ημέρες**. (Παρατηρημένη ασυνέπεια — βλ. Q-06.) |
| **R-10** | Μοντέλο τιμολόγησης (C, άρθρο 4) | `pricing.model` | `fixed_price` → πίνακας οροσήμων με ποσοστά· `time_and_materials_capped` → ρήτρα ανώτατου ποσού + πίνακας ημερήσιων χρεώσεων ανά προφίλ **και απαλοιφή** του πίνακα οροσήμων. Και τα δύο εμφανίζονται στα δείγματα. |
